```
novarium/

├── README.md
├── docs/                  # 기획·설계 문서 (이 폴더)
│   └── PROGRESS.md        # 진행 기록 — 작업 끝날 때마다 갱신
├── client/                # 게임 화면 (Vite + TypeScript + Phaser + pixelfx)
│   ├── src/
│   │   ├── scenes/        # Boot, Title, Hub, Village, Dorm, Greenhouse, PetCare, Lesson, Practice
│   │   ├── fx/            # pixelfx 연결 계층 (FxLayer, 이펙트 프리셋)
│   │   ├── api/           # 서버 호출 (fetch 래퍼, 타입)
│   │   ├── ui/            # 대화창, HUD, 상점 패널
│   │   └── data/          # 정적 데이터 (맵, 대사)
│   └── public/assets/     # 스프라이트, 타일셋 + CREDITS.md
└── server/                # 백엔드 (Spring Boot)
    └── src/main/java/com/novarium/
        ├── auth/          # 회원가입, 로그인, JWT
        ├── student/       # 학생(플레이어), 기력, 별가루
        ├── magic/         # 마법, 숙련도, 수업 세션
        ├── pet/           # 펫, 먹이, 훈련, 성장
        ├── dorm/          # 방, 가구 배치
        ├── shop/          # 상점, 구매
        ├── inventory/     # 보유 아이템
        ├── quest/         # 일일 퀘스트, 이벤트 리스너
        └── common/        # 예외, 응답 포맷, 시간·랜덤 공급자
```

패키지는 **도메인(기능)별**로 나눈다. 각 도메인 안에 `controller / service / domain(entity) / repository / dto`.

## 3. pixelfx ↔ Phaser 연결

pixelfx는 자체 프레임 버퍼(`createFrame`)에 그리고 `composite`로 `ImageData`에 합성한다. Phaser와는 이렇게 잇는다.

```
Phaser Scene
 └─ FxLayer (client/src/fx/FxLayer.ts)
     ├─ frame = createFrame(320, 180)
     ├─ imageData = new ImageData(320, 180)
     ├─ texture = scene.textures.createCanvas('fx', 320, 180)
     ├─ update(dt): 활성 이펙트 update → clearFrame → draw(back) → draw(front)
     │              → composite(frame, imageData.data, 투명) → texture.context.putImageData → texture.refresh()
     └─ spawn(effectModule, {x, y, palette, flip}) / 끝난 이펙트 자동 제거
```

- 배경·캐릭터 스프라이트는 Phaser가 그리고, FxLayer 이미지를 그 위(front) / 아래(back) 두 장으로 둔다.
- 투명 합성이 잘 안 되면 대안: 이펙트를 `tools/render.mjs --sheet`로 스프라이트 시트로 구워서 Phaser 애니메이션으로 재생.
- **M1의 첫 작업이 이 연결 검증(스파이크)** 이다. 결과를 PROGRESS.md에 기록.

## 4. API 설계 (v1)

공통: `/api/v1`, JSON, 인증 필요 API는 `Authorization: Bearer <token>`.
에러 응답: `{ "code": "OVERLAP", "message": "가구가 겹칩니다", "details": {...} }`

### 인증
| 메서드 | 경로 | 설명 |
|---|---|---|
| POST | /auth/signup | 이메일, 비밀번호 |
| POST | /auth/login | → accessToken, refreshToken |
| POST | /auth/refresh | 토큰 재발급 |

### 학생
| 메서드 | 경로 | 설명 |
|---|---|---|
| POST | /students | 아바타 생성 (이름, 주 원소, 외형) — 계정당 1명 |
| GET | /students/me | 내 정보 (별가루, 기력은 조회 시점 기준 계산값) |
| POST | /students/me/rest | 쉼터 휴식 (+기력) |

### 마법·수업
| 메서드 | 경로 | 설명 |
|---|---|---|
| GET | /magic/spells | 마법 목록 + 내 해금 여부 |
| GET | /magic/mastery | 원소별 숙련도 |
| POST | /lessons | 수업 시작 → lessonSessionId (기력 차감) |
| POST | /lessons/{id}/result | 정확도·시간 제출 → 등급, 숙련도 증가, 별가루 |

### 펫
| 메서드 | 경로 | 설명 |
|---|---|---|
| GET | /pets | 내 펫 목록 (hunger는 계산값) |
| POST | /pets/{id}/hatch | 부화 |
| POST | /pets/{id}/feed | 먹이 (body: itemId) |
| POST | /pets/{id}/pet | 쓰다듬기 |
| POST | /pets/{id}/train | 훈련 (body: stat) → 성공 여부, 상승량 |

### 기숙사·상점·인벤토리
| 메서드 | 경로 | 설명 |
|---|---|---|
| GET | /dorm/room | 내 방 배치 + version |
| PUT | /dorm/room | 배치 전체 저장 (body: version, placements[]) |
| GET | /shops/{shopCode}/items | 상점 목록 |
| POST | /shops/{shopCode}/purchase | 구매 (itemId, quantity) |
| GET | /inventory | 보유 아이템 |

### 퀘스트
| 메서드 | 경로 | 설명 |
|---|---|---|
| GET | /quests/daily | 오늘의 퀘스트 + 진행도 |
| POST | /quests/daily/{id}/claim | 보상 수령 |

## 5. 데이터 모델 (ERD 초안)

```
account(id, email UK, password_hash, created_at)
  1─1 student(id, account_id UK, name, main_element, appearance_json,
              stardust, energy, energy_updated_at, version)
student 1─N mastery(student_id, element, value)                      PK(student_id, element)
student 1─N lesson_session(id, student_id, element, started_at, submitted_at, grade)
student 1─N pet(id, student_id, species, stage, hunger, hunger_updated_at,
                affection, str, agi, mag, obtained_at, pet_count_today, version)
student 1─1 dorm_room(id, student_id UK, version)
dorm_room 1─N furniture_placement(id, room_id, item_id, x, y, rotation)
item(id, code UK, name, type[FURNITURE|FOOD|EGG], width, height, price, theme)
student 1─N inventory(student_id, item_id, quantity)                 PK(student_id, item_id)
shop(code PK, name) N─M item  → shop_item(shop_code, item_id)
student 1─N daily_quest(id, student_id, quest_date, type, target, progress, claimed)
```

- 시간 의존 값(기력, 배고픔)은 **저장 시각 + 경과 시간으로 계산**. `Clock`을 주입해 테스트 가능하게.
- `item`, `shop`, 마법 목록 같은 고정 데이터는 Flyway 시드 SQL로 넣는다.

## 6. 테스트 전략

| 대상 | 방식 |
|---|---|
| 도메인 규칙 (배치 검증, 등급 계산, 기력 계산) | 순수 단위 테스트 — 가장 촘촘하게 |
| 서비스 (구매 트랜잭션, 훈련) | Mockito 또는 @SpringBootTest + H2 |
| 리포지토리 | @DataJpaTest |
| API | MockMvc로 대표 성공/실패 케이스 |
| 클라이언트 | 핵심 계산 로직만 Vitest, 화면은 수동 확인 + 스크린샷 |

## 7. 보안 체크리스트

- 비밀번호 BCrypt, JWT 시크릿은 환경 변수(`.env`, 커밋 금지)
- 모든 `/{id}` 리소스는 **소유자 확인** (다른 학생의 펫 훈련 불가)
- 보상·확률은 서버 계산, 클라이언트 값 신뢰 금지
- 입력 검증 `@Valid`, 가구 좌표·수량 범위 검사
- ECC `/security-scan`, `springboot-security` 스킬로 마일스톤마다 점검
